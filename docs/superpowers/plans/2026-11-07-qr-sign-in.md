# QR Sign-in on the Car Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A parked Android Automotive car connects Spotify, Last.fm and ListenBrainz by showing a QR code that a phone scans, with no Parachord account and no browser on the car.

**Architecture:** A one-time pairing. The car registers a session with a small relay on `parachord.com`, then shows a QR code carrying the session id and a fresh public key. The phone posts back end-to-end encrypted results: a service sign-in through web pages on `parachord.com/pair/*`, or a handover from the Parachord app. The car polls, decrypts and stores them through the existing sign-in paths. Protocol, crypto, relay client and handover logic live in `shared/commonMain`. The car UI is Android only. The phone side is Android and iOS.

**Tech Stack:**
- **Relay:** a Cloudflare Worker with a Durable Object (`parachord-website/worker`, vitest pool-workers).
- **App:** Kotlin Multiplatform with Ktor, `dev.whyoleg.cryptography` (cryptography-kotlin) and kotlincrypto SHA-256.
- **Android:** Compose and ZXing core for QR rendering.
- **iOS:** SwiftUI.

**Spec:** `docs/superpowers/specs/2026-11-07-qr-sign-in-design.md`. Read it first. This plan fixes the exact values the spec leaves open.

**Two repositories:**
- `parachord-website`, branch `feat/pair-relay`: Tasks 1–3.
- `parachord-android` (GitHub `Parachord/parachord-mobile`), branch `feat/qr-sign-in`: Tasks 4–12. Task 4's first commit also adds the spec and this plan.

## Global Constraints

- No Parachord user account and no server-side identity. The relay holds only short-lived records.
- Records and unwritten sessions expire **10 minutes** after `POST`. A record is deleted when the car reads it.
- The relay never logs request bodies.
- Services, exact ids: `spotify`, `lastfm`, `listenbrainz`. SoundCloud is out of scope (spec Non-goals): the relay rejects `soundcloud` with 400, and the car keeps its existing SoundCloud Connect.
- Return URL, exact: `https://parachord.com/pair/callback`.
- QR URL, exact shape: `https://parachord.com/link/{session}?s={service}&c={pkceChallenge}#k={carPublicKey}`. Omit `c` for `lastfm` and `listenbrainz`.
- Only `/link/*` is claimed as an Android App Link or iOS Universal Link. `/pair/*` must never be claimed.
- Session id and read secret: 16 random bytes each, base64url without padding.
- Encryption: see "Envelope v1" below. It must be byte-compatible between WebCrypto, Android and iOS.
- `listenbrainz` arrives only by handover from the phone app. No web page ever accepts a ListenBrainz token.
- Shared logic in `shared/commonMain`. No JVM-only APIs (CLAUDE.md "KMP / shared/commonMain rules"). Run `./gradlew :shared:iosSimulatorArm64Test` on any change to shared code.
- Existing phone sign-in flows keep their current behavior. QR is used only when `packageManager.hasSystemFeature(PackageManager.FEATURE_AUTOMOTIVE)`.

### Envelope v1 (fixed)

- **Car key:** ECDH P-256. The public key is uncompressed raw, 65 bytes, base64url without padding (`k`).
- **Sender:** generates an ephemeral P-256 key pair per record. `shared = ECDH(ephemeralPrivate, carPublic)`, 32 bytes.
- **Key:** `HKDF-SHA256(ikm = shared, salt = UTF-8(session), info = UTF-8("parachord-pair-v1/" + service), length = 32)`.
- **Encryption:** AES-256-GCM, random 12-byte IV, 128-bit tag, `AAD = UTF-8(session + "/" + service)`.
- **Wire JSON:** `{"v":1,"epk":"<b64u 65 bytes>","iv":"<b64u 12 bytes>","ct":"<b64u ciphertext||tag>"}`.
- **Plain fallback**, only for `spotify` codes: `{"v":0,"plain":{"type":"code","code":"…"}}`. The car rejects `v:0` for any other service.
- **Plaintext payloads (JSON):**
  - `{"type":"code","code":"…"}`: spotify.
  - `{"type":"token","token":"…"}`: lastfm, from the web.
  - `{"type":"session","key":"…","username":"…"}`: lastfm, by handover.
  - `{"type":"token","token":"…","username":"…"}`: listenbrainz, by handover.
  - `{"type":"error","reason":"denied"|"failed"}`: any service.

### Relay API (fixed)

| Request | Body / header | Responses |
|---|---|---|
| `POST /api/link/{session}` | `{"readHash":"<b64u SHA-256(readSecretBytes)>"}` | 201; 409 if it exists; 400 for a bad id |
| `PUT /api/link/{session}/{service}` | an envelope, at most 4096 bytes | 204; 404 if unregistered or expired; 409 if already written; 400 for an unknown service or bad body; 413 if too big |
| `GET /api/link/{session}` | header `X-Pair-Read: <b64u readSecret>` | 200 `{"records":{"<service>":<envelope>,…}}`, which can be `{}`, and returned records are deleted; 403 for a wrong secret; 404 if expired |

Every response carries `Cache-Control: no-store`. CORS allows `PUT` from `https://parachord.com` only; the apps don't need CORS. Rate limit: 60 requests per minute per IP across these routes, using the Workers Rate Limiting binding. If the account's plan lacks it, a per-IP counter in the same Durable Object namespace is fine.

## Review Focus

1. **A code expires while the person is still signing in on the phone.** The callback page's `PUT` gets 404 and must say "This code expired. Show a new code on the car." The car's screen must offer a new code. Tested in Tasks 1, 2 and 8.
2. **The person declines on the service's page** (`error=access_denied`). The callback page posts an `error/denied` record, and the car stops waiting and says the sign-in was declined. Without this, the car spins for 10 minutes. Tested in Tasks 2 and 6.
3. **The same QR is scanned twice, or a sign-in is repeated.** The second write gets 409; the page says "Already sent" and is not treated as a failure. Tested in Tasks 1 and 2.
4. **The car leaves the QR screen, or loses its network, mid-flow.** Polling stops on leave. While the screen is open, network errors are retried with no error shown until expiry, and nothing is stored twice. Tested in Task 6.
5. **The phone's browser lost the key** (the service's own app handled the sign-in). A Spotify code still goes through as `v:0`. A Last.fm token is never sent unencrypted, and the page says to try again in the browser. Tested in Task 2.
