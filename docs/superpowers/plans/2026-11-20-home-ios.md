# Home: iOS (PR 6 of 6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace iOS's Home with desktop's new Home page, drawn from the same shared `HomeSession` Android's Home uses, section for section.

**Architecture:**
- The inputs move to shared code. `AndroidHomeSources` is almost all shared repositories, so it becomes a commonMain `RepositoryHomeSources`. Each app passes only its playback flows and its plug-in gate.
- What a Home tap plays (a tile, a mix, Recent Loves, a playlist, an album) moves into a shared `HomeQueues`, which Android's view model also switches to.
- A new iosMain bridge, `IosHomePage.kt`, holds one app-wide `IosHomeSession`. It wraps `HomeSession` and the art lookups and flattens `HomeState` into plain DTOs (`IosHomePage`), as `IosRecommendationsPage.kt` does. Its suspend calls never throw into Swift.
- Swift draws only. A `HomeModel` watches the page with `FlowWatcher`, and `HomeScreen.swift` is rebuilt as small section views. Each section shows when the shared `HomeSections` flag says so, in the spec's order.

**Tech Stack:** Kotlin Multiplatform (commonMain + iosMain), coroutines/Flow, SwiftUI (iOS 17 `@Observable`), the hand-rolled `IosContainer`.

## Global Constraints

- **No rules in Swift.** Which sections show is `HomeState.sections`. Text is `HomeCopy` / `UiMessages`, read through the DTOs. Colours are `PC.*` tokens and `ResolverColor`. A rule that's missing gets added in shared code, with a test, and is drawn on both apps.
- **Bridged suspends never throw.** Every `IosHomeSession` suspend function catches, rethrows `CancellationException`, and returns a DTO with a `message`. None is `@Throws`.
- **Exact names.** Add no Kotlin property named `description`, `hash` or `debugDescription` to a Swift-facing type; use `blurb` / `text`.
- **Counts** (shared constants, never literals in Swift): `HOME_ROW_CARDS` 6, `HOME_HALF_ROW_CARDS` 3, `HOME_CONCERT_CARDS` 4, `HOME_JUMP_TILES` 4 (a 2×2 grid), `GETTING_STARTED_PLAYLISTS` 3, the 500-character Ask cap (`ChatPrompt.cap`).

## Review Focus

1. **Coming back to Home** (re-tapping the tab recreates `HomeScreen`, or returning from a pushed page):
   - Recommendations and mixes don't reload within 10 minutes.
   - An Ask field the user typed into isn't reseeded.
   - The example gets a new phrasing only on a fresh entry into Home, not on a return from a pushed page.
   - The session is an app-wide singleton for this reason. Task 4's `IosHomePageTest` covers it.
2. **A bridged call that fails** (offline mix lookup, a playlist read, a catalog album lookup) shows the shared message and never aborts the app. Task 4 covers it.
3. **The Jump back in tile for what's playing disappears** once it plays. iOS pushes the playing context from the coordinator's 1 s tick, so the tile goes within a second. Task 2's shared queue contexts and Task 4's test cover it.
4. **A new user on iOS** gets the getting-started layout, never a blank Home or an endless skeleton. The plug-ins load in `AppBootstrap`, and the session waits at most `GETTING_STARTED_DECIDE_TIMEOUT_MS`. Checked in the simulator with an erased device in Task 8.
5. **A concert card with no tour artist** has no tap and no photo lookup, and VoiceOver reads it as one element whose only action is Tickets. Task 7, plus the on-device VoiceOver check in the test plan.

### Task 2: Shared `HomeQueues`, and where a mix's "Playing from" goes

**Item 7, the proposal:** a mix queue's context id is the mix's link, and "Playing from" opens the mix in the service-playlist view, on both apps.
- Today the mix context is `{type: mix, id: mix.id, name}` (desktop's), and nothing maps it, so "Playing from" opens nothing on either app.
- The link is what `ServicePlaylistView` / `ServicePlaylistScreen` need. A `PlaybackContext` field can't be added instead: Kotlin defaults aren't visible from Swift, so every Swift `PlaybackContext(type:name:id:)` call would break.
- So, in `HomeModel.kt`:
  - `jumpTileContext(JumpTile.Mix)` becomes `PlaybackContext(MIX_CONTEXT, mix.title, mix.url)`.
  - `jumpCandidate` / `jumpBackInTiles` compare mixes by `url`. A mix's url and id are both unique, and the url is what the queue carries.
- In `PlaybackContext.kt`, `playbackContextDestination` maps `MIX_CONTEXT` with an id to `ContextDestination.ServicePlaylist(id, name)`.
- Desktop keeps `m.id`, and its "Playing from" for a mix also opens nothing. Ask the user whether to file a desktop ticket; don't file one.
