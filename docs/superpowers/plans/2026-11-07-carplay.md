# CarPlay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A CarPlay audio app with Android Auto's library (Playlists, Loved Songs, Collection Radio), Now Playing with the heart and Spinoff, Up Next and error messages, built on car logic shared with Android Auto.

**Architecture:** Android Auto's portable rules (browse tree, ids, caps, what a tap plays, which buttons show) move to `shared/commonMain` package `com.parachord.shared.car`; Android's `PlaybackService` and a new iOS CarPlay scene both render them. iOS first gets the groundwork CarPlay needs: playback that starts without the phone's screen, sign-ins readable on a locked launch, Now Playing info and remote commands that follow every engine, and car-only playback rules.

**Tech Stack:** Kotlin Multiplatform (commonMain, commonTest on JVM + iOS simulator), Media3 (Android), Swift + CarPlay framework (`CPTemplateApplicationScene`, `CPListTemplate`, `CPNowPlayingTemplate`), MediaPlayer (`MPNowPlayingInfoCenter`, `MPRemoteCommandCenter`).

**Spec:** `docs/superpowers/specs/2026-11-07-carplay-design.md`

## Global Constraints

- Shared logic in `shared/commonMain`; every shared change runs `./gradlew :shared:testDebugUnitTest :shared:iosSimulatorArm64Test` as well as `./gradlew :app:testDebugUnitTest`.
- Android Auto behaves exactly as before: same media ids (`parachord_root`, `browse:playlists`, `browse:loved`, `action:collection-radio`, `playlist:<id>`, `playlist-shuffle:<id>`, `playlist-track:<position>:<playlistId>`, `loved-track:<id>`, `search-track:<n>`), same titles, order, caps (500 playlist tracks, 100 loved songs) and buttons.
- iOS deployment target stays 17.0. New Swift files get their 4 pbxproj entries per `iosApp/AGENTS.md`; target-level changes (entitlements build settings, scene manifest) use the `xcodeproj` gem.
- The CarPlay entitlement `com.apple.developer.carplay-audio` goes only in a simulator-only entitlements file (`CODE_SIGN_ENTITLEMENTS[sdk=iphonesimulator*]`); device builds stay signable.
- No Swift-facing Kotlin property named `description`, `hash` or `debugDescription` (CLAUDE.md KMP rule 11).
- No `System.currentTimeMillis`, `java.*`, `Dispatchers.IO` in commonMain (CLAUDE.md KMP rules).
- Nothing changes on the phone's lock screen or Control Center for Apple Music or Spotify beyond what Task 5 records.
- "In the car" = a CarPlay scene is connected.
- Copy: "Open Spotify on your phone to play this" (Android's existing string, now shared).
- Branch: `feat/carplay` in a worktree (`.worktrees/carplay`); follow CLAUDE.md's worktree rules for every gradle command.

## Review Focus

1. **Empty library** (no playlists, no collection, empty playlist): every list returns empty without crashing; Collection Radio and an empty playlist's Shuffle play nothing and show no error. Tests in Task 1.
2. **Stale id** (a playlist or loved track deleted between showing the list and the tap): `playRequest` returns null, nothing plays. Tests in Task 1.
3. **Playlist ids containing `:`** and huge playlists: ids round-trip; the list is capped at 500 but playing plays every row. Tests in Task 1.
4. **Cold launch from the car with the phone locked**: plugins, the queue and sign-ins are ready, so a tap plays. Checked in Tasks 3, 4 and 9.
5. **Car disconnects mid-track, or the phone opens while the car is connected**: playback continues; car-only rules switch off when the scene disconnects. Checked in Task 6 and 9.
